Need official mechanism for rebuilding a failed store
  - Move rebuild logic in CLI to aspen.server.rebuild package
    - Remove CLI
  - Rebuild operations are managed the same way as Store TransferIn/TransferOut
    - StoreManager polling function sees a Store assigned to the device in the Rebuilding state
      - Start/Resume the rebuild process
  - Use "rebuild-state.yaml" file in root directory of the storage device to indicate that the store is
    being rebuilt and should not be loaded normally (similar to transfer in/out)
    - May also serve to hold any beneficial checkpointing state
  - Rebuild process may periodically checkpoint to disk to speed up the recovery process in the
    event of a crash
    - One exampe could be the UUID of the last restored object
    - That way it can pick up from near where it left off rather than staring from the beginning
