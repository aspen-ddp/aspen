Every open weakness in docs/safety/* (the "## Open weaknesses" section at the end of each document) is listed below
once, grouped where one change addresses several ids. Completed items are removed; their record is in git history.
Item numbers are stable (other documents may cite them), so gaps are expected. Priority is by the worst plausible
consequence, then likelihood, then cost. A cheap fix with a large payoff moves up within its tier. All findings in
this pass were derived by reading the code; none has a reproducing test yet. CONFIRMED = mechanism traced end to end;
PLAUSIBLE = mechanism real, trigger uncertain.

Ordering of consequence: lost committed data or a split decision > systemic loss of many stores > resurrection,
overwritten update or permanent replica divergence > liveness (hangs, stalls) > performance > analysis/docs.

Working rule for every item:
  1. Re-read the finding and the code.
  2. Reproduce it with a test (deterministic, LockstepThreading where possible). If it cannot be reproduced, record
     why in the finding and remove or downgrade it.
  3. Fix it, then remove the finding from the doc's Open weaknesses, fold the guard into the design text (present
     tense, no history), and update the module CLAUDE.md.
  4. If the fix narrows a finding rather than closing it, state the residual explicitly in the finding.

As items are completed, remove them from this document but keep the numbers the same for remaining items.

PRIORITY 4: liveness (hangs, stalls, livelocks)
-----------------------------------------------

4.2  Rebuild's pending-allocation sweep waits forever on a transaction held by its own silence: RB-W1     [S]
     CONFIRMED. sweepPending waits on any listed unresolved allocation with no bound; rule G holds T while a store
     of T is silent, and the rebuilding store is silent until the sweep finishes. Fix: stop waiting once T's
     start is past horizon + expiry margin (the rebuilt store is muted for T and will be marked), and skip Txs
     started after the rebuild began. Not covered by the bounded read of 4.3 (it is a query).

4.3  Reads with no timeout stall the rebuild walk/sweep and the repair scan: RB-W4 + Backlog item         [M]
     CONFIRMED. A never-completing client.read holds a rebuild slot and cancel cannot end it; healthy pools'
     rebuilds stall behind it. Same root and fix as Backlog.txt "Repair scan stalls on an allocation held past
     expiry" (bounded read; a timed-out read is a failed object). The repair agent notes the Backlog item is
     broader than stated: any object below its read threshold or a key that stays NotRestorable stalls the scan
     the same way; update the Backlog text. Do the bounded read once for both consumers.

4.4  A finalization action that retries forever keeps the missed-update marker from running: R-W2          [S]
     CONFIRMED. The marker runs only once every other action settles; allocation/deletion/split/join/tail-removal
     actions retryUntilSuccessful, so an unrelated outage blocks repair marks for its duration. Fix: run the
     marker once the others settle or after a bound (FinalizationStallAfter), whichever first. Correct the
     "failing action" wording in server/transaction/CLAUDE.md and the MissedUpdateFinalizationAction.execute
     scaladoc.

4.5  A stale repair pass resets the lock-deferral count; a hot object never reaches a proof: RP-W2         [S]
     PLAUSIBLE. DeferralState.record forgets on any non-lock result, and parking resets the stale count, so
     stale/parked/locked alternation never reaches proofAfterDeferrals. Fix: do not reset the lock count on a
     stale pass (or keep parking once started until a complete pass).


PRIORITY 5: performance and hygiene
-----------------------------------

5.1  Driver ignoring an abort TxFinalized is dropped from the store's driver map: P-W3                     [S]
     CONFIRMED (also raised by transaction-recovery). Only after a split decision. Fix: remove only if the
     driver concluded after receiveTxFinalized.

5.2  Markerless directory at a store path the tree does not list is loaded and served: RB-W5              [S]
     PLAUSIBLE, narrowed: code no longer leaves one (copies are retired with a marker, deletes are rename-first),
     so only a directory put back by hand remains. Fix: have the reconcile close (and retire) a loaded store whose
     device entry is absent.

5.3  CRL completion handlers run on the writer thread before the next write: CRL-W4                        [S]
     PLAUSIBLE. Network sends in handlers serialize on the device's one writer thread under group commit. Fix:
     ordered completion executor; queue WriteComplete at once. Measure first.

5.4  CRL shutdown() leaves pending Futures uncompleted: CRL-W5                                             [S]
     CONFIRMED mechanism. droppingCrlState / crlDropsRunning keep a store until process restart. Fix: fail
     every pending and later call with CrlClosed.
