1.2 [Q-W10, X section 5] Remove quarantine: it has no valid trigger and loses committed data.       CONFIRMED, M
    transaction-requirements.md Q-W10 (replaces repair-process RP-W6 and RP-W7, flaws in quarantine itself). Verified
    against the code, `Tx.issueCommits` quarantines in three cases:
      (a) a live voter's failed re-check: since lock order (`Tx.awaitLockHolders`) only an invariant violation (state
          changed under the locks, two conflicting commits) causes it. Log it as one, skip and report the object.
      (b) a recovered voter's failed re-check: within the margin it was applied before the crash and superseded
          (refcounts carry update serials, so they are chained too). Treat it as applied.
      (c) `RequirementsApplyer.mayReinsertDeletedKeys`: a genuine normal-operation ambiguity, not a below-threshold
          workaround. A re-applied blind Insert/`DoesNotExist` of k passes again after a later delete of k. Remove
          the ambiguity: a commit deleting k waits until no unconcluded Tx whose CRL state holds a blind Insert of k
          on that object remains (as `Frontend.awaitAllocationsDurable` does for deletion after allocation); a
          re-applied Insert of an absent key is then known unapplied and is applied. The wait costs only a key
          delete that closely follows a blind insert of the same key: nothing on the ordinary commit path.
    Quarantining in (b)/(c) leaves a counted voter with neither T's update nor its lock, and its verification counts
    its own stale copy: one crash plus one store legitimately missing T loses T. Then delete `Frontend.quarantine`,
    `QuarantineVerifier`, `StoreRepairer.verifyObject`, `ObjectQuarantined`, the quarantine half of `keptForReplay`,
    `reappliedTraceless`, and their tests. Correct transaction-requirements.md 8.5 / 10.5c / 10.7(e), repair-process.md
    10.2, cross-document-review.md 2.3 and 5, the store/transaction/repair CLAUDE.md files and the scaladoc.

PRIORITY 3: systemic loss protection
------------------------------------

(The correlated false "store lost" design item remains in Backlog.txt.)

3.1 [CRL-W9] A save file is declared lost against a growth cap the device config sets.            PLAUSIBLE, S
    crash-recovery-log.md CRL-W9. `StoreLoader.neverFits` uses `maxAdmissionLimitBytes`, which follows
    `crl-max-streams` (0 for an invalid growth bound) as read at this open; lowering or mistyping it fleet-wide marks
    every arriving or kept state above the new cap `rebuild-required`. Fix: judge against the limit at
    `CrlSizingDefaults.MaxMaxStreams`, so only a transaction above `T` is lost; otherwise wait offline, warned.

3.2 [X-W4] The leftover-CRL drop releases the admission charge of a store that landed while it ran.  PLAUSIBLE, S
    cross-document-review.md X-W4. `DeviceReconciler.dropLeftoverCrlState` calls `admission.releaseRetained(storeId)`
    on completion, which also releases a loaded state charged meanwhile by `CrlAdmission.tryChargeLoaded`; Lemma C can
    then fail and a rotation can fail the CRL (W6). Fix: release only what was retained when the drop was issued, or
    skip the release while the store is loaded or opening.


PRIORITY 4: liveness (hangs, stalls, livelocks)
-----------------------------------------------

4.1 [X-W5, RB-W12] A store whose open or rebuild-complete removal fails is left unserved and untracked until restart. CONFIRMED, S
    cross-document-review.md X-W5, rebuild-process.md RB-W12. `StoreLoader.handleBackendOpened`'s generic
    `Failure(e)` and `StoreRebuilds.startRebuild`'s `Adopt` branch on a failed `clearRebuildCompleteMarker` leave an
    Active store neither loaded nor in `offlineStores`, and every reload pass filters `offlineStores`; meanwhile
    `StoreCopies.release` deletes the superseded copy. One unit of `w - t` margin lost silently. Fix: on any such
    failure leave the store offline (`leaveOffline` / `keepUnpromotedCopyOffline`) and have the device check retry an
    Active offline store carrying no marker, with backoff as `retryStoresAwaitingSpace` does. Correct the
    `clearRebuildCompleteMarker` scaladoc.

4.2 [SL-W9] The fresh CRL replacing a lost device CRL is created in place, beside the device's stores.  CONFIRMED, S
    systemic-loss-protection.md SL-W9. A crash mid-rename leaves `<n>.crl` beside `<n>.crl.tmp`, refused as
    `CrlSizingMismatch` forever; a failed preallocation (ENOSPC) leaves `.crl.tmp` files, so every scan declares the
    CRL lost again and piles up `crl.lost-*` directories. The device never loads, so its `pending-delete/` copies are
    never released. Fix: create the replacement in a scratch directory (swept at device load) and rename it to `crl/`
    durably once complete. Correct the `SimpleCRL.createStreamsIfNew` scaladoc and crash-recovery-log.md 5.1 step 4.

4.3 [Q-W9] Votes blocked by lock-order waits can form a cross-store cycle that lasts until expiry.   PLAUSIBLE, S
    transaction-requirements.md Q-W9 (raised independently by the Paxos audit). `Frontend.voteBlocked` blocks every new
    vote on an object while a committed lockless Tx waits in `Tx.awaitLockHolders`; two such waits at two stores can
    each block the vote the other's holder needs, stalling the object about 30 s until expiry ends the holders. Fix:
    block only votes that collide with the waiting commit's changes.


PRIORITY 5: performance and hygiene
-----------------------------------

5.1 [X-W3, X section 5] A commit learned from the UnackedCommits tree is reported non-late to expiry and adopted. CONFIRMED, S
    cross-document-review.md X-W3. `Tx.statusForExpiry` reports `late = lateOutcome` (false for a tree-learned
    resolution), so a peer's `ExpiryTally.decide` adopts a non-late commit, its cache records a non-finalized
    `Committed`, and a relayed driver re-runs T's finalization long after T was finalized. Idempotent, but wasted
    repair and metadata work, and it contradicts paxos-transactions.md 10.2 / transaction-recovery.md 7.2. Fix: report
    a tree-learned resolution as saved (`Unresolved`, with its vote) or as `late`.

5.2 [SL-W10] A lost device CRL marks a finished rebuild awaiting its flip.                            CONFIRMED, S
    systemic-loss-protection.md SL-W10. `DeviceDiscovery.openDeviceCrl` spares only `holdsOwnState` directories; a
    `rebuild-complete` copy has no save file, held nothing in the lost CRL, yet is retired and rebuilt again. Fix:
    `holdsOwnState` also spares a `rebuild-complete` directory.
