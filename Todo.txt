3.2 [SL-W19] A failed read of an FSIF compaction move fail-stops the store, whatever the error.
    CONFIRMED. Effort S. systemic-loss-protection.md, cross-document-review.md section 5,
    server/store/backend/fsif/DESIGN.md (4.2, L18).
    fsif Compaction.copied fail-stops on any move-read failure, including a rejected io task (runIo), though nothing
    is written yet and Compaction.cancel can abandon the move; compaction runs on every FSIF store, so a host-wide
    EMFILE/ENOMEM or saturated io executor fail-stops many stores at once (D6). Fix: abandon and retry the move on a
    read failure that is not evidence of damage (as the client read path does since X-W22); rewrite DESIGN.md's L18
    and its "a client read only returns CorruptedObject" passage.


PRIORITY 4: liveness (hangs, stalls, livelocks)
-----------------------------------------------

(SL-W9, a device without room for the CRL replacing its lost one, is in Backlog.txt's systemic-loss entry.)

4.1 [P-W9] A held late commit that then resolves by a non-late commit never expires.
    CONFIRMED. Effort S. paxos-transactions.md.
    Tx.lateCommitHeld stays set after a non-late TxResolved(commit) applies, and Tx.mayExpire requires
    !lateCommitHeld, so the Tx, its CRL record and admission and its driver live until the store reloads.
    Fix: mayExpire on !(lateCommitHeld && oresolution.isEmpty), or clear the flag in Tx.resolved.

4.2 [RB-W18] A missing store whose directory returns while its rebuild request fails is left unserved.
    PLAUSIBLE. Effort S. rebuild-process.md.
    The Missing Stores pass silences the store and calls requestRebuild; if the directory comes back and the request
    fails other than by collision, nothing asks again and no pass loads an unmarked offlineStores store with an
    Active entry, so it is unserved until restart while its pool counts it writable. Fix: keep a host-local record of
    the stores the pass declared and request again while the entry stays Active.

4.3 [CRL-W18] The admission limit's proof fails for small streams in a large ring.
    PLAUSIBLE. Effort S. crash-recovery-log.md, cross-document-review.md section 3.
    (n-2)*S/2 - S/16 satisfies Lemma B only while 118*(n-1) <= S/16 + 8192; CrlSizingDefaults.resolve accepts 1 MiB
    streams up to 1024 streams (broken past 625), so a W6 fail-stop within admission unloads the device until
    restart. Fix: subtract 118*(n-1) in limitAt, or refuse/cap such configs.


PRIORITY 5: performance and hygiene
-----------------------------------

5.1 [R-W12] A sibling store on the same host relays a stale non-finalized commit, re-running T's finalization actions.
    CONFIRMED. Effort S. transaction-recovery.md, paxos-transactions.md 10.2.
    Store.handleTransactionMessage's sender relay (msg.from != msg.to && !entry.finalized) ignores the self-send rule,
    so a same-host sibling answers an idle recovery driver with a non-late TxResolved from the shared status cache;
    actions re-run and, without a late answer within errorTimeout, marks, entries and stubs are written for every
    store. Safe (cross-document-review 2.6 checks every shipped action), but wasteful.
    Fix: skip the sender relay of a non-finalized entry when the sender is a store of this host.

5.2 [RB-W20] An out-of-space write in retryFailures is recorded as an unreadable object.
    CONFIRMED. Effort S. rebuild-process.md.
    RebuildingStore.retryFailures never calls latchOutOfSpace, so the pass fails "incomplete" pointing at
    accept-rebuild-loss instead of REBUILD OUT OF SPACE, and with acceptLoss set, objects peers can supply are
    recorded as accepted losses. Fix: latchOutOfSpace in its recover; check the latch before lossAccepted.

5.3 [X-W25] The join finalization action removes an upper-tier entry by its key alone.
    PLAUSIBLE. Effort S. cross-document-review.md.
    JoinFinalizationAction re-run (or delayed) after a later split at the same minimum deletes that split's index
    entry; lookups still follow links, so performance only. Fix: delete only when the value is deleteNode's pointer,
    under the key's revision as read.

5.4 [X-W26] A failed stat of a moved store's arrival file drops its arrival margin; remaining os.exists uses.
    PLAUSIBLE. Effort S. cross-document-review.md 2.2.
    StoreLoader.readArrivedAt uses os.exists, so a failed stat drops AcceptorSinceMargin from a moved store's load
    floor. Fix: FileStat there (failure counts as arrival now), and FileStat for the remaining existence tests that
    cross-document-review 2.2 lists (DeviceDiscovery.adoptionClass, StoreRebuilds.retireForeignCopy /
    discardLostStore / backendFailed, StoreTransfers.startIn markers, openDeviceCrl), which today only delay.

5.5 [X-W27] A recovered vote's refcount re-check rests on an unenforced update-serial convention.
    PLAUSIBLE. Effort S. cross-document-review.md 2.3, transaction-requirements.md 10.5(c).
    Pins and DescriptionValidator accept a RefcountUpdate that does not advance ObjectRefcount.updateSerial (e.g.
    (5,2)->(5,1)); no shipped caller does it, but the re-check would then pass on a replay. Fix: refuse such an
    update in TransactionBuilder and DescriptionValidator.
