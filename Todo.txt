overwritten update or permanent replica divergence > liveness (hangs, stalls) > performance > analysis/docs.

     why in the finding and remove or downgrade it.

     tense, no history), and update the module CLAUDE.md.

As items are completed, remove them from this document but keep the numbers the same for remaining items.

PRIORITY 2: resurrection, overwritten updates, permanent replica divergence
---------------------------------------------------------------------------

2.1 [S] Q-W18: a recovered commit vote re-adopts object data its CRL state dropped (PLAUSIBLE).
    After persistWithoutUpdateOf (a later deletion's wait), a retransmitted or delayed client prepare carrying this
    store's data passes Tx.adoptObjectUpdates, which has no guard for a Tx that already voted commit. On a commit, a
    deleted allocated object gets a fresh Allocating state, passes its re-check and is recreated with nothing
    reported (a blind-Insert key is re-inserted but reported). Fix: adoptObjectUpdates adopts nothing once
    disposition == VoteCommit; a commit voter held all its data when it voted.

2.2 [S] RP-W12: repair's dropOccupant can delete a live object (PLAUSIBLE). An FSIF index freed by a deletion is
    reusable in the same transaction (FsifIndexAllocationStrategy); a repair install meeting RepairSlotOccupied(C)
    reads the AllocationTree, finds C unlisted (its AllocationFinalizationAction not yet landed), and its later
    repairDeletion can arrive after C's Tx was finalized and left Frontend.referenced: C's slice is deleted with no
    mark, silently spending the t - r margin. Fix: drop the occupant only on a read proving its own deletion
    (InvalidObject.provesDeletion, type from the FSIF header), or re-read the repaired object first. Cross-check
    rebuild-process FS6, which relies on the same id-checked repair delete.

2.5 [S] RB-W21: a copy that serves between rebuild passes leaves the resumed walk's done part stale with no mark
    (PLAUSIBLE). A Missing Stores directory that comes back after the checkpoint is served by a restart's device
    load (a load retry waits while the store is declared or Rebuilding), acknowledges commits, and is then retired
    by retireForeignCopy, but the next pass resumes the checkpoint: its acknowledged updates on walked objects are
    never marked (t = r, exactly t voters: t - 1 < r copies). Fix: retireForeignCopy deletes the staging directory before marking or fail-stopping
    a foreign copy, forcing a first pass.

PRIORITY 4: liveness (hangs, stalls, livelocks)
-----------------------------------------------

4.1 [S] RB-W24: persistently failing rebuilds starve the queued rebuilds of their device (PLAUSIBLE).
    startRebuilds orders by pool index and startRebuild ignores the backoff; maxConcurrentRebuilds failing stores
    that sort first (e.g. incomplete passes awaiting accept-rebuild-loss) retake the slots at every check. Fix: skip
    a store inside its backoff (scheduleRebuildRetry) when choosing what to start.

4.2 [S] X-W31: keepUnpromotedCopyOffline silences a store served from another device of this host (PLAUSIBLE).
    It sets the router's offline mark by store id (DeviceControl.markStoreOffline), unlike
    StoreLoader.keepMarkedCopyOffline: the served store turns non-repairable (HostStoreView) and
    DeviceShutdown.storesToClose skips it. Trigger: an Unconfirmed/Superseded settle after a same-host transfer or
    re-placement served the store elsewhere. Fix: mark the router only when no copy is served or opening here.

(SL-W9, a device without room for the CRL replacing its lost one, is in Backlog.txt's systemic-loss entry.)


PRIORITY 5: performance and hygiene
-----------------------------------

5.1 [M] X-W30 + P-W10 + RB-W22 + SL-W25: the remaining os-lib existence tests (CONFIRMED). Replace every os.exists / os.isDir / os.isFile under server/ with FileStat, deciding per site whether a
    failed stat waits, throws or is safe either way, and add a test that fails on any new use outside FileStat.
    Sites with findings: DeviceDiscovery.bringIntoService skips the ArrivedAtFile (P-W10: a lower forget floor after
    adoption); RebuildingStore.isRebuildCompleteFor swallows a read error and retires a finished copy (RB-W22: a
    wasted rebuild; throw and wait instead); DeviceMarkers.isFailed loads a tombstoned device (SL-W25, within B19).
    The rest are listed in cross-document-review X-W30. Then make server/host/CLAUDE.md's FileStat rule true.

5.2 [S] Q-W19: a commit that applies nothing still waits in lock order and for its turn (CONFIRMED). A recovered
    non-voter, an applied stub or notOwedHere runs awaitLockOrder and holdForTurn in resolvedAndAllObjectsLoaded
    before doCommit decides to apply nothing, withholding votes (then CollisionWait aborts) and unsettling repair.
    Fix: decide "applies nothing" first, with one predicate shared with doCommit.

5.3 [S] RB-W23: a rebuilding store's router silence can be cleared and is never restored (CONFIRMED).
    startRebuild marks the router offline once; clearOfflineUnlessHeld looks only at devices' offlineStores, which a
    destination that never held the store does not list (same-host replaceRebuild). The host then answers
    StoreNotFound for the rest of the rebuild: re-reads and dropped routes only. Fix: count running rebuilds in
    clearOfflineUnlessHeld, or re-mark at each reconcile while the rebuild runs.
