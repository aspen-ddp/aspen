# Gossip Membership over QUIC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `QuicNet`'s all-to-all `HostHeartbeat` with scalecube-cluster membership running over QUIC, and gossip `StoreMoved` / `HostEndpointChanged` so hosts drop stale cached locations at once.

**Architecture:**
- A scalecube `Transport` implementation (`QuicClusterTransport`) carries scalecube's Java-serialized messages as opaque bytes inside a new Aspen message, `ClusterTransportMessage`, addressed by HostId. Member addresses are `<HostId uuid>:0`.
- A wrapper, `HostMembership`, owns the scalecube `Cluster`, turns membership events into online/offline/restarted events (via a pure `MemberTracker`), and broadcasts and receives `Gossip`.
- `QuicNet` creates the wrapper in host mode, re-dials on a changed boot id, and drops cached mappings on gossip.
- `Host` broadcasts `StoreMoved` after a transfer commits, and reconciles its own endpoint at startup.

**Tech Stack:** Scala 3, scalecube-cluster 2.7.12 (Reactor), Netty QUIC, ScalaPB, ScalaTest.

**Spec:** `docs/superpowers/specs/2026-10-22-gossip-membership-design.md`

## Global Constraints

- Dependency: `"io.scalecube" % "scalecube-cluster" % "2.7.12"` from Maven Central. It brings in `scalecube-cluster-api` and `scalecube-transport-api` transitively. Do NOT add `scalecube-transport-netty`.
- Member address: exactly `s"${hostId.uuid}:0"`. Member id: scalecube's default random UUID. Never set `memberId`.
- Boot id: one `UUID.randomUUID()` per `QuicNet` instance, generated by `QuicNet` and independent of scalecube's member id.
- Seeds: the HostIds in `initialBootstrapConfig.hosts`. The local host may be in the list; scalecube filters it out.
- Only hosts join. A client-mode `QuicNet` (`ohost == None`) creates no `HostMembership`.
- ZMQ behaviour is unchanged. `HostHeartbeat` stays in `Message.scala`, the proto and the codecs.
- `idleTimeout`'s effective default stays `heartbeatPeriod * 3`. Keep the `heartbeatPeriod` constructor parameter for that.
- Gossip carries no values, only "what is stale": `StoreMoved(storeId)` and `HostEndpointChanged(hostId)`.
- Production scalecube timings: the scalecube defaults (ping 1000 ms, ping timeout 500 ms, sync 3000 ms, gossip 200 ms, suspicion mult 5).
- Tests: in-process, short timings, poll on conditions. No fixed sleeps, except where a test must prove that something does *not* happen. Those sleeps stay under 1 s.
- Project style: Scala 3 quiet syntax, indented if/then/else, comment density like `QuicNet.scala`.
- Run tests from the repo root with `sbt 'testOnly *SuiteName'`.

## Review Focus

1. **The local host is in its own seed list.** Every bootstrap host is. Joining must succeed and the host must not mark itself online, offline or restarted. Pinned by `local host in seed list is ignored` (Task 4).
2. **Undecodable bytes**, either a `ClusterTransportMessage` payload or a gossip payload. They are logged and dropped, and later valid traffic still works. Pinned by `garbage payload is dropped and transport keeps working` (Task 2) and `undecodable gossip is dropped` (Task 4).
3. **Traffic before `start` or after `stop`/shutdown.** It is dropped without throwing, and a send after `stop` returns an error `Mono`. Pinned by `send after stop errors, receive after stop is ignored` (Task 2).
4. **`HostEndpointChanged` for a host this node has never resolved.** It must not start a host lookup. Pinned by `endpoint gossip for an unknown host starts no lookup` (Task 5).
5. **A client-mode `QuicNet` receives a `ClusterTransportMessage`.** It is ignored without error. Pinned by `client mode ignores cluster transport messages` (Task 5).

### Task 3: `MemberTracker` (membership events → host events)

**Files:**
- Create: `src/main/scala/org/aspen_ddp/aspen/common/network/implementations/quic/gossip/MemberTracker.scala`
- Test: `src/test/scala/org/aspen_ddp/aspen/common/network/implementations/quic/gossip/MemberTrackerSuite.scala`

**Interfaces:**
- Produces:
  - `enum HostEvent { case Online(hostId: HostId); case Offline(hostId: HostId); case Restarted(hostId: HostId) }`
  - `final class MemberTracker`. It is not thread-safe; the caller serialises access. Methods:
    - `def added(hostId: HostId, memberId: String): List[HostEvent]`
    - `def removed(hostId: HostId, memberId: String): List[HostEvent]`
    - `def isOnline(hostId: HostId): Boolean`
    - `def onlineHosts: Set[HostId]`

Rules. They need no time window: this is my reading of the spec's "within a short window", and it is simpler. It holds because the tracker remembers the last member id per host for the life of the process.
- `added`:
  - The host already has a live member id → `List(Restarted(h))`.
  - Otherwise, the host's last-known member id exists and differs → `List(Online(h), Restarted(h))`.
  - Otherwise → `List(Online(h))`.
  - Re-adding an id that is already live → `Nil`.
- `removed`: drop the id from the live set. If the live set becomes empty → `List(Offline(h))`, else `Nil`. Removing an unknown id → `Nil`.

test("new member while old is live is Restarted, no Offline"):

    - `def offline(hostId: HostId): Unit`
    - `def restarted(hostId: HostId): Unit`
    - `def gossipReceived(g: Gossip): Unit`
  - `final class HostMembership(localHost: HostId, val bootId: UUID, seeds: List[HostId], config: GossipConfig, sendFn: ClusterTransportMessage => Unit)`:
    - `def start(): Unit`. Starts the cluster asynchronously and never blocks the caller.

    - `def isOnline(hostId: HostId): Boolean`

- Behaviour:
  - Build the cluster with `new ClusterImpl().transportFactory(() => _ => transport)`. Set the membership seeds to `seeds.map(addressOf)` and apply `config` to the failure detector, gossip and membership settings.
  - Ignore membership events whose address doesn't parse, or whose HostId is `localHost`.
  - Map `isAdded` → `added`, and `isRemoved` / `isLeaving` → `removed`.
  - `onGossip` with the `"aspen/gossip"` qualifier → `decodeGossip`, then call `gossipReceived` on listeners. Undecodable gossip is logged and dropped.
  - All tracker updates and listener calls run in order on one single-thread daemon executor owned by the wrapper (`DaemonThreads.factory("aspen-gossip")`), never on scalecube's scheduler. A throwing listener is logged and does not stop the others.

  - Reads `client.getHostState(hostId)`. If all four fields match, it completes `false` without a transaction.
  - Otherwise it writes `hostState.copy(...)` with a `KeyRevision(HostState.StateKey, …)` requirement, following the pattern in `BaseAspenClient.scala:340-350`, under `client.transactUntilSuccessful`. On commit it calls `net.broadcastGossip(HostEndpointChanged(hostId))` and completes `true`.
  - If it fails, it logs and retries via `backgroundTasks.schedule(Duration(5, SECONDS))`. The returned `Future` reflects only the first attempt.

## Notes for the implementer

- Scalecube's `ClusterImpl` keeps the seed list fixed after start. A bootstrap config refresh does not change it, and that is fine: seeds matter only for the first join, and after that scalecube syncs with members it already knows.
- `MembershipEvent.isLeaving` happens only on a graceful scalecube shutdown. Aspen has none in production, but test teardown triggers it.
- If scalecube logs loudly at INFO through scribe-slf4j, lower `io.scalecube` to WARN in `TestLoggingConfig`, not in production config.
